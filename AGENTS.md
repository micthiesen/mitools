# AGENTS.md

This file provides guidance to Codex and other coding agents working in this repository.

## What this is

`@micthiesen/mitools` is Michael's shared TypeScript utility library, published to npm and consumed by sibling projects (`omni-notify`, `condo`, `lobster`, `presspods`). Since 4.0.0 it is an Effect 4 library: every I/O, timing, retry, resource or concurrency function returns a typed `Effect`, services are `Context.Service` classes with layers, and the library never runs an effect itself. It ships code **and** shared tooling config: `biome.shared.json`, `tsconfig/node.json` + `tsconfig/library.json`, and `baseVitestConfig` (`./vitest` export) are part of the published package; changes to them ripple into every consumer.

Edit `AGENTS.md` and `.agents/skills/` directly. Codex uses these native files directly; no compatibility links or generation step are needed. `README.md` is the consumer front door, `MIGRATION.md` the v3 to v4 map, `CHANGELOG.md` the release notes; a change to a public API updates all three in the same commit.

## Effect first

- **Every production effect is an `Effect`.** Functions that perform I/O, wait, retry, acquire resources or coordinate concurrent work return `Effect` values with typed expected errors and compose with Effect schedules, scopes and services. Effects run only at consumer boundaries and in tests; this package contains no `Effect.runSync` / `runPromise` / `runFork` at all; the one synchronous contract it must satisfy (Effect's own `Logger.log`) is met by `emitUnsafe`, a fire-and-forget over a `FiberSet` fiber that `Logger.flush` tracks. The Effect-returning function takes the PLAIN name (`getDoc()`, `entity.upsert()`, `scheduler.start`); a Promise adapter exists only where an external contract requires one and is named `fooPromise`; a synchronous fire-and-forget adapter over a fiber takes Effect's `Unsafe` suffix. Do not add adapters for convenience.
- **Errors.** Domain failures are `Data.TaggedError` classes with fields a consumer can match on and a `message` override that names the operation and the cause (`CorruptRowError`, `InvalidScheduleError`, `PushoverError`, ...). Untyped boundaries (better-sqlite3, cbor, `node:fs`, Node streams, a Promise API) are wrapped once with `operationErrors(source)` from `src/errors/index.ts`, never with a per-file `XError { cause: unknown }` that nothing matches by tag. No `Effect.catch` that hides a failure a consumer should see; log-and-continue is only for a whole-collection read skipping one corrupt row, a scheduled task's run, and a notification hook.
- **Services and layers.** The real seams are `Context.Service` classes: `Logger`, `Sqlite`, `Docstore`, `Scheduler`, `Pushover`, `Karakeep`, plus Effect's own `HttpClient`, `Console`, `Clock`, `ConfigProvider`. Each exports `layer` (explicit options), `layerConfig` (reads the same env keys v3 used, through `Config`) and a test layer (`layerMemory`, `layerCapture`, `layerNoop`, `layerDisabled`). Export layers, never singletons; `Entity` is the one pure-constructor class and its methods require `Docstore`. Resources are `Effect.acquireRelease` inside `Layer.effect` (Effect 4 has no `Layer.scoped`; `Layer.effect` strips `Scope`).
- **Idioms.** Named effectful functions are `Effect.fn("Service.method")` (module-private helpers and generics `Effect.fnUntraced`). Time is `Clock.currentTimeMillis` / `DateTime.now`, never `Date.now()`, so `TestClock` drives expiry, retries, timeouts and cron. Randomness is `Random.*`. Retries are a `Schedule` (`retrySchedule`). Cron is Effect's `Cron`/`Schedule.cron`, six fields with seconds first. Validation is `Schema` (zod is gone). Library-internal logging is `Effect.log*` with `Effect.annotateLogs({ logger: "Name" })`; the mitools `Logger` adapter turns that into a named line for consumers.
- **Effect references, in order of authority for the installed version:** `node_modules/effect/AGENTS.md` (the authoring guide shipped with the package), `node_modules/effect/ai-docs/src/index.md` and its topic examples, `node_modules/effect/dist/<Module>.d.ts` as ground truth for what exists and its signature, then <https://effect.website/docs/v4/> for narrative docs. Prefer these over memory: Effect 4 renamed and reshaped much of Effect 3 (`Context.Service` classes, `Result` instead of `Either`, `Option.fromNullishOr`, `parseUnsafe`-style suffixes, one-parameter `Schema.Schema`), and lint will not catch an idiom that merely compiles.
- **Lint proves only what is promoted.** `pnpm lint` runs the `@effect/tsgo` diagnostics (the TypeScript 7 build of the Effect language service; `@effect/language-service` only patches TypeScript 5) with the rules this project relies on promoted to `warning` in `tsconfig.json`, because the plugin's suggestion tier never reaches a CLI run. `prepare` re-patches `tsc` after every install, so `typecheck` and `build` fail on the same diagnostics. A new rule worth enforcing gets promoted there, not remembered.
- **Consumers.** The reference consumer for boundary and error conventions is `wt` (`/Users/michael/.wt`: `AGENTS.md` "Effect first", `docs/architecture.md` "Effect boundary", `src/core/errors.ts`). `omni-notify` is the heaviest real consumer (logging, entities, scheduling, pushover, logfile); design an API change for it. `effect` is a peerDependency (`>=4.0.0-rc.112 <4.1`) plus a devDependency, never a regular dependency, never re-exported, so a consumer ends up with one copy.

## Releasing

CI (`.github/workflows/npm-package.yml`) runs check, lint, typecheck, tests and build, then publishes to npm on every push to `main` and silently skips already-published versions. To release: bump `version` in `package.json` (deps-only or docs → patch; new APIs → minor; breaking → major), commit as `Bump to X.Y.Z`, push. There is no manual publish step. A major gets a `CHANGELOG.md` entry and `MIGRATION.md` coverage.

## Architecture

- **Independent modules, subpath exports.** There is no root index; consumers import `@micthiesen/mitools/<module>`. Each entry in `package.json#exports` maps to a file under `src/` (built to `dist/` by tsc). Adding a module = new `src/<name>/` + an `exports` entry + a README row + a MIGRATION note if it replaces something.
- **ESM-only, NodeNext resolution**: relative imports must use `.js` extensions.
- **Errors** (`errors/`): `OperationError`, `operationErrors(source)`, `causeMessage`. Leaf module; everything imports it.
- **Config** (`config/`): `baseConfigFields` / `baseConfig` (Effect `Config` for `LOG_LEVEL`, `PUSHOVER_*`, `DOCKERIZED`, `DB_NAME`), `isSensitiveKey`, `redactConfig`, `logConfig`. Services read their own keys; this exists for consumers that want one typed object. `toml.ts` builds a `ConfigProvider` from TOML (`smol-toml` into `ConfigProvider.fromUnknown`; `withDottedPaths` makes `"paths.main_clone"` resolve because `fromUnknown` does not split dotted names), `errors.ts` maps a `ConfigError` to `ConfigRemedyError { key, problem, remedy }` (missing vs invalid is decided by probing the provider, since Effect renders both as the same schema issue), `aliases.ts` is `withAliases`.
- **CLI** (`cli/`): `runMain` (fork, SIGINT/SIGTERM interrupt, exit-code mapping, flush on every path, `process.exit`), `renderFailure`, `exitCodeFor`. The one `Effect.runFork` outside the boundary modules.
- **Persistence** (`persistence/`), three layers over one better-sqlite3 connection:
  - `Sqlite` (`./sqlite`) owns the connection (WAL; `layerConfig` prefixes `/data/` when `DOCKERIZED`) and `transaction(name, fn)`.
  - `Docstore` (`./docstore`) stores CBOR blobs in a single `blobs` table: `pk`, `data`, plus `entity`, `version`, `expires_at`, `updated_at`. `Docstore.layer` ensures the schema (idempotent `PRAGMA table_info` guard). Every read filters expired rows; `cleanupExpired` reclaims them. Point reads fail `CorruptRowError`; collection reads warn and skip. Free accessors (`getDoc(pk)`) mirror the service methods. `DocstoreSync` is the synchronous surface used inside `transaction`.
  - `Entity<Data, PKProps>` (`./entities`) layers documents on the docstore, keyed off the `entity` column. Keys use a length-prefixed, type-tagged codec (`$name#s3:abc#n5`). Construction is pure; methods are effects requiring `Docstore` and resolve `Option`. **Migration is one-shot, not lazy:** run `Entity.migrateAll()` once at startup.
  - `Table<T>` (`./table`): `Table.make(options)` creates typed real SQL tables idempotently; `insert` is INSERT OR IGNORE and resolves whether a row was inserted.
- **Logging** (`logging/`): `Logger` service (threshold, ordered `LogSink`s with the console as default, hooks in a `FiberSet` so `Logger.flush` can wait, tap); `Logger.named(name)` builds hierarchical names via `.extend` and tags lines with `.channel("attention")`; sinks live in `sinks.ts` (`consoleSink`, `captureSink`, `dailyFileSink` with a Queue-backed writer fiber and mtime retention, `channelSink`/`levelSink`/`filterSink`); `tracer.ts` is `Logger.layerTracer`, a `Tracer` whose spans log at debug through `emitUnsafe` (it reads `Logger` inside a generator because of the import cycle with `Logger.ts`); `Logger.layerAdapter` routes `Effect.log*` in and lifts Effect's minimum level to `All` so the tap sees everything; `Logger.layerCapture` for tests. `LogLevel` string values are persisted by consumers: keep them stable.
- **Scheduling** (`scheduling/`): `Scheduler` service; `ScheduledTask<E, R>` records with six-field cron, `jitterMs`, `runOnStartup`. `register` captures the task's services from the caller's context; `start` forks one fiber per task into the caller's scope; runs are uninterruptible so `shutdown` waits for a run in flight.
- **Services**: `Pushover` and `Karakeep` talk through `HttpClient` (`effect/unstable/http`); `LogFile` serializes writes with a `Semaphore`.
- **Async** (`async/`): the shared `Schedule` presets (`exponentialBackoff`, `spacedUpTo`, `lockContention`; `retrySchedule` builds on the first) and `makeDebounced` (`debounce.ts`, scoped; the `Unsafe` adapters run through a scope-owned `FiberSet.makeRuntime`). A poll-until-deadline loop is `Effect.repeat` with `spacedUpTo`, not a helper.
- **Proc** (`proc/`): the subprocess runner ported from wt on `node:child_process` (Effect's `effect/unstable/process` needs `@effect/platform-node` and has no process-group kill or `timedOut`). Invariants: `ProcConcurrency` (a `Context.Reference` holding a `Semaphore`, 8 permits) taken under `Effect.uninterruptibleMask`; `detached: true` and `process.kill(-pid)`; SIGTERM, 1 s grace, SIGKILL, full join before the permit is released; `RunResult.timedOut` distinguishes a killed command from an empty answer; the specs are real subprocesses (`it.live`) because OS behaviour is the subject.
- **Locks** (`locks/`): `wx`-created lock files with JSON `LockMeta`; staleness is a dead pid (EPERM counts as alive) or an old mtime; waits use `lockContention`; `withLock` is `acquireUseRelease`. No flock in Node, so a wedged live holder is reclaimed only after `staleMs`.
- **Probes** (`probes/`): three-valued answers. `probePort` reports `unknown` on a timeout (never `free`); `lsofScan` retries a blown budget once and then returns `complete: false`; the higher-level readers return `Option` (`None` = the scan did not finish).
- **Boundaries** (`boundary/`, `react/`, `testing/`, `cli/`): the only modules that run an effect, because a Promise-returning `queryFn`, a React cleanup, a test runner and a process entry point are external contracts. Everything routes through an `EffectRunner` (`{ runPromise, runFork }`, satisfied by `ManagedRuntime`) so tests inject one built from `TestClock.layer()`.

## Tests

`*.spec.ts` colocated with source, written with `@effect/vitest` (`it.effect` provides `TestClock`, `TestConsole` and a `Scope`; `it.live` only for real fs/stream behaviour). Persistence specs use `Docstore.layerMemory` (in-memory SQLite), so nothing is written to disk. Time-dependent behaviour is driven with `TestClock.adjust`; there are no wall-clock sleeps.
